# Gmail誤送信防止拡張機能 要件定義書

Nov 14, 2026 · @Tatsk Gunj

## 1. 概要

Gmailの送信操作を横取りし、宛先・本文・添付を確認させてから送信するChrome拡張機能を開発する。業務メールの誤送信（宛先誤り、添付漏れ、宛名誤り、誤字）をなくすことが目的。

| 項目 | 内容 |
| --- | --- |
| 目的 | 業務メールの誤送信をなくす |
| 形態 | Chrome拡張機能（Manifest V3） |
| 対象環境 | PC版Chrome（Edgeでも動作可）上のGmail（mail.google.com） |
| 利用者 | 一般公開（Chrome Web Store） |
| 参考 | Thunderbirdのアドオン「Confirm-Address」（宛先の個別チェック）、「Check and Send」（送信前チェック） |
| 対象外 | Gmailモバイルアプリ（拡張機能が動作しないため） |

## 2. 配布・公開方針

Chrome Web Storeで一般公開し、GitHubでソースコードも公開する。メール本文を読む拡張機能のため、ソース公開を信頼性の担保に使う。

| 項目 | 方針 |
| --- | --- |
| Chrome Web Store | 開発者登録（一度きりの登録料5ドル）のうえ一般公開する |
| GitHub | ソースを公開する。ライセンスはMITを想定 |
| プライバシーポリシー | GitHub Pagesで公開する。データを外部に送信しないこと、端末内にのみ保存することを明記する |
| ストア審査対応 | 権限はmail.google.comのみに限定する。リモートコードは読み込まない。「単一用途」を誤送信防止として説明する |
| Gmail API | 使わない（制限付きスコープの審査と年次のセキュリティ評価を避けるため）。画面上の情報だけで完結させる |
| リポジトリの注意点 | 業務の宛先台帳・辞書・実在のメールアドレスをコードやテストデータに含めない |

## 3. 機能要件：送信確認

すべての送信操作で確認ダイアログを表示し、宛先を全件チェックしないと送信できないようにする。

### 3-1. 送信の捕捉

- 送信ボタンのクリック、ショートカット（Ctrl+Enter／Cmd+Enter）、「送信日時を設定」（予約送信）を捕捉する
- 対象画面：新規作成、返信、全員に返信、転送、インライン返信、ポップアウト、全画面表示
- Gmailの表示言語に依存しない方法で送信ボタンを特定する（「送信」という文言で探さない）

### 3-2. 確認ダイアログ

| 表示項目 | 仕様 |
| --- | --- |
| To／Cc／Bcc | アドレスごとにチェックボックスを表示し、全件チェックで送信ボタンが有効になる |
| 会社名での表示 | ドメインではなく会社名でまとめて表示する（例：A社 2名／B社 1名）。台帳にない場合はドメインを表示 |
| 社内・社外の区別 | 社外を強調表示する |
| 複数社混在 | 社外の会社が2社以上含まれる場合に警告する |
| 件名 | 表示する（空欄なら警告） |
| 本文 | 冒頭の数行（宛名部分）をプレビュー表示する |
| 添付ファイル | ファイル名の一覧を表示し、チェック対象に含める |
| 操作 | 「送信」「キャンセル（編集に戻る）」 |

### 3-3. 宛先区分の指定

| 区分 | 単位 | 効果 |
| --- | --- | --- |
| 社内扱い | ドメイン／アドレス | 送信元アドレスのドメインは自動で社内扱い。追加分は手動登録。社外強調・複数社混在の判定から除外し、確認を簡易にできる |
| 要注意 | ドメイン／アドレス | 毎回強調して表示する。確認省略より優先する（重要顧客、名前が似ている人、退職者など） |
| 確認省略 | アドレス | ダイアログを出さない（自分宛てのメモ送信など）。初期設定では無効 |

- 区分が重なる場合の優先順位は、要注意 ＞ 社内 ＞ 社外とする
- 確認省略は宛先の区分とは別に判定する。機能が有効で、かつすべての宛先が確認省略アドレスの場合のみダイアログを省略する
- フリーメール（gmail.com、yahoo.co.jp、icloud.com、outlook.jpなど）は、ドメイン単位ではなくアドレス単位で判定する。フリーメールの一覧は組み込みの固定リストとする（フェーズ1）
- 送信元がフリーメールの場合、ドメインは自動で社内扱いにせず、送信元アドレス自身のみを社内扱いにする

## 4. 機能要件：自動検知

送信前に以下を自動で検知し、確認ダイアログ上で警告する。返信時の引用部分（過去メール）は判定対象から除外する。

### 4-1. 添付漏れ

- 本文に添付を示すキーワードがあり、添付ファイルが0件の場合に警告する
- キーワード初期値：添付、別添、別紙、同封、送付、資料をお送り、ファイルをお送り、データをお送り、ご査収、見積書、請求書、PDF、attached、attachment、enclosed（設定画面で編集可）
- 調べるのは本文のみ（件名は調べない）。大文字・小文字、全角・半角は区別しない
- 相手に送付・添付を頼んでいる文や、相手が送ってくれたことに触れている文（「請求書を送付してください」「ご送付いただいた資料」など）は対象外とする
- 添付が無いことを述べている文（「添付ファイルはありません」など）は対象外とする
- Googleドライブのリンクを添付ありとみなすかは設定で選べる（初期設定：みなす）。対象は drive.google.com と docs.google.com のリンクに限る（本文にURLを貼り付けただけの、リンクになっていない文字列も含む）

### 4-2. 宛名と宛先の不一致

| 検知内容 | 方法 |
| --- | --- |
| 宛名と宛先の照合 | 本文冒頭の宛名（「株式会社〇〇 △△様」）を抽出し、Toの表示名・連絡先台帳の氏名・会社と照合する |
| 添付ファイル名と宛先の不一致 | 「見積書\_A社.pdf」をB社のドメインに送ろうとしている場合に警告する |
| 本文中の他社名 | 宛先と異なる、台帳登録済みの会社名が本文に含まれる場合に警告する（使い回しメールの修正漏れ対策） |

### 4-3. 誤字脱字・記載漏れ

| 区分 | 検知内容の例 |
| --- | --- |
| 未記入のプレースホルダー | 〇〇、XX、●●、【 】、{name} などが残っている |
| 日付と曜日の不一致 | 「11月13日（木）」→ 実際は金曜日 |
| 敬称の誤り | 「御中」と「様」の併用、「各位様」、宛名に敬称がない |
| 社名表記 | （株）と株式会社の混在、前株・後株の誤り（台帳の登録社名と照合） |
| 重複・脱字 | 「のの」「をを」など同じ文字の連続、二重助詞 |
| よくある誤変換 | ユーザー辞書に登録した誤りと照合 |
| 表記ゆれ | 全角・半角の英数字混在 |
| その他 | 件名が空、署名がない、本文が空 |

### 4-4. 宛先の妥当性

| 検知内容 | 方法 | 警告の初期値 |
| --- | --- | --- |
| Cc漏れの通知 | その会社宛てのメールで、過去によくCcに入っていた人が今回入っていない場合に知らせる | オン |
| 初めて送るドメイン | 送信実績のないドメインが宛先にある場合に強調する（似たドメインへの誤送信対策） | オン |

## 5. 機能要件：連絡先・会社台帳

送受信の過程で連絡先と会社を自動で台帳化し、会社とドメインを紐づける。この台帳を宛名照合・Cc漏れ通知・会社名表示に使う。取得はGmailの画面から少しずつ蓄積する方式とし、Gmail APIは使わない。

### 5-1. 記録対象

- 自分が送信した相手（To・Cc）
- 届いたメールのCcに入っていた人のうち、既知の会社のドメインと一致する人
- 上記の相手から届いたメールの署名で情報を補完する（メルマガ等の不要な連絡先は記録しない）

### 5-2. 取得項目

| 項目 | 取得元 | 想定精度 |
| --- | --- | --- |
| メールアドレス | 送信元・宛先 | 高 |
| 氏名 | 送信元の表示名、自分が書いた宛名（「〇〇様」） | 高 |
| 会社名 | 署名（「株式会社」「合同会社」「Inc.」などを手がかりに抽出）、宛名の1行目 | 中〜高 |
| 電話番号 | 署名（番号の形式から抽出）。代表番号と携帯は別項目 | 高 |
| 部署・役職 | 署名 | 中 |
| やりとりの役割 | To／Ccのどちらで何回入ったか、最終やりとり日 | 高 |

### 5-3. 会社とドメインの紐づけ

1. 会社名が取れた人のドメインを、その会社に紐づける
2. 会社名が取れていない人も、ドメインが一致すれば同じ会社に所属させる
3. 人物ごとにTo／Ccの役割と回数を記録する

| ケース | 対応 |
| --- | --- |
| フリーメール | ドメインと会社は紐づけず、人物単位で会社を持たせる |
| 1社で複数ドメイン | 1社に複数のドメインを登録できる |
| 1ドメインに複数社 | 自動では決めず、利用者に確認を求める |
| 表記ゆれ | 正式名称と別名を持たせ、どの表記でも検索にヒットさせる |

### 5-4. 精度と運用のルール

- 引用部分の署名は抽出対象から除外する（別人の署名との取り違え防止）
- 署名が変わった場合（異動・転職）は最新情報で上書きし、変更前は履歴として残す
- 自動抽出した情報は「自動」、利用者が確認・修正したものは「確定」として区別する
- 一覧表示、編集、CSVの書き出し・取り込み、一括削除ができる

### 5-5. 会社名での検索

- 拡張機能のポップアップと、メール作成画面の両方から検索できる
- 結果は会社 → ドメイン → 人物の順に表示する（氏名、部署・役職、メール、電話番号、To／Ccの役割と回数、最終やりとり日）
- その会社とのメールでよく同席する別会社（代理店・パートナーなど）も表示する
- 作成画面では、検索結果からそのままTo・Ccに追加できる

## 6. 警告の設定と設定画面

検知項目ごとに、警告するかどうか（オン／オフ）を選べるようにする。

| 設定 | 動作 |
| --- | --- |
| オン | 該当した場合にダイアログへ警告を表示する。警告が出ても、そのまま送信できる |
| オフ | チェックしない |

フェーズ1の検知項目（添付漏れ、プレースホルダー、日付と曜日の不一致、件名が空、複数社混在）の初期値は、すべてオンとする。

送信を止めるのは、宛先と添付の確認（全件にチェックを入れるまで送信できない）のみとする。検知項目に「ブロック」（解消するまで送信できない）の段階は設けない。

**設定画面の項目**

- 社内扱い・要注意のドメイン／アドレス登録、確認省略のアドレス登録と有効・無効の切り替え
- 添付キーワードの編集
- 誤字辞書の登録
- 検知項目ごとの警告のオン／オフ
- 連絡先・会社台帳の閲覧、編集、CSVの書き出し・取り込み、一括削除
- 初期設定のままで誰でも使える状態にする（添付キーワードは日本語・英語を標準搭載）

## 7. 非機能要件

| 項目 | 要件 |
| --- | --- |
| セキュリティ | 本文・宛先・台帳はブラウザ内でのみ処理し、外部に送信しない。AIによる誤字・脱字チェックもChrome内蔵のAIで端末内で処理する。権限はmail.google.comのみ |
| データ保存 | 設定はchrome.storage、連絡先・会社台帳は件数増加に備えてIndexedDBに保存する |
| 端末間の共有 | 自動同期はしない。CSVの書き出し・取り込みで対応する |
| 性能 | 送信操作から0.5秒以内に確認ダイアログを表示する |
| 保守性 | Gmailの画面構造の変更に備え、要素の取得処理を一か所にまとめる |
| フェイルセーフ | 拡張機能側でエラーが起きた場合は「チェックできませんでした」と表示し、黙って送信させない |
| 複数アカウント | Gmailの複数アカウント切り替えに対応する。設定はアカウント共通とし、社内の判定は作成画面ごとの送信元アドレスから導く |
| 多言語 | Gmailの表示言語に依存せず動作する。拡張機能のUIは日本語・英語 |
| 併用推奨 | Gmail標準の「送信取り消し」を30秒に設定するよう案内する |

## 8. AIによる誤字・脱字チェック

Chrome内蔵AI（Gemini Nano）のPrompt APIのみを使う。利用者のAPIキーを登録する方式と、自前サーバーを経由する方式は採用しない（外部送信と料金が発生するため）。

| 方式 | 外部送信 | 費用 | 評価 |
| --- | --- | --- | --- |
| Chrome内蔵AI（Prompt API） | なし | 無料 | 採用。ただし空き容量22GB以上、メモリ16GB以上などの端末要件あり |
| APIキー登録方式 | あり | 利用者負担 | 不採用（外部送信と料金が発生するため） |
| 自前サーバー経由 | あり | 開発者負担 | 不採用（運用・プライバシー対応・課金設計の負担が大きい） |

**処理の流れ**

1. 送信操作を止めて、確認ダイアログをすぐに表示する（AIの結果を待たない）
2. 件名と本文（引用部分を除く）をPrompt APIに渡して解析する
3. 誤字・脱字の候補（誤りの箇所、修正案、理由）をJSON形式で受け取る
4. 候補を検証し、確認ダイアログの「誤字・脱字の候補」の欄に表示する

**ルール**

- 初期設定では無効。設定画面で有効にする。モデルのダウンロード（初回のみ）は、設定画面のボタンから利用者が始める
- 対応していない端末では、設定画面にその旨を表示する。ほかの機能はそのまま使える
- 解析が終わる前でも送信できる。候補は表示するだけで、送信は止めない
- 解析に失敗した場合は、欄に「AIチェックは実行できませんでした」と表示し、送信は止めない（フェイルセーフの例外）
- AIが指摘した箇所が元の文面に存在しない候補は表示しない
- 候補ごとに「修正する」ボタンを出し、修正案をメールの件名・本文に反映できるようにする。取り違えを防ぐため、該当する箇所が1か所に決まる場合だけ反映する（引用部分は書き換えない）
- 反映した後は、書き換えた行をメール本体から読み直して、書き換えた部分を強調して表示する。あわせて「元に戻す」と「メールで確認」（ダイアログを閉じ、メールの画面で該当箇所を選択した状態にする。送信はしない）を用意する
- AIが有効な場合は、Gmailを開いた時点でモデルを先に読み込み、最初の解析を速くする
- 外部からスクリプトを読み込まない（ストアのリモートコード禁止に対応）

署名からの連絡先抽出の精度向上にAIを使うかは、フェーズ3で検討する。

## 9. 開発フェーズ

3段階で開発し、フェーズ1で誤送信事故の大半をカバーする。

| フェーズ | 内容 | 効果 |
| --- | --- | --- |
| フェーズ1 | 送信の捕捉、確認ダイアログ（件名が空・複数社混在の警告を含む）、社内・要注意・確認省略の指定、添付漏れ、プレースホルダー、日付と曜日の照合、AIによる誤字・脱字チェック | 宛先誤り・添付漏れ・記載漏れ・誤字の防止 |
| フェーズ2 | 連絡先・会社台帳の自動作成、会社名検索、宛名と宛先の照合、添付ファイル名・本文中の他社名チェック、Cc漏れ通知、初めて送るドメインの警告、会社名での宛先表示 | 宛名誤り・使い回しミス・打ち間違いの防止 |
| フェーズ3 | 誤字辞書の拡充（敬称の誤り、社名表記、重複・脱字、よくある誤変換、表記ゆれ、署名がない、本文が空を含む）、AIによる署名抽出の精度向上 | 文面品質の向上 |

## 10. 将来の拡張候補・未決事項

**将来の拡張候補**

- 過去メールからの連絡先の一括取り込み：利用者が自分のアカウントで実行するGASをGitHubに同梱し、CSVで拡張機能に取り込む（Gmail APIの審査が不要）

**未決事項**

- [x] AI校正の方式：Chrome内蔵AI（Gemini Nano）のPrompt APIのみ。APIキー方式は採用しない
- [x] 拡張機能の名称：Send Check for Gmail（日本語・英語とも同じ）
  - 名前に「Gmail」を使えない場合（ストアの規約・商標の都合）は「Send Check for mail」とする
  - 商標の決まりに合わせ、ストアと拡張機能一覧での表記は「Send Check for Gmail™」とする
  - GitHub のリポジトリ名とパッケージ名は send-check-for-gmail
- [x] プライバシーポリシーの文面：docs/privacy-policy.md（英語版は privacy-policy.en.md）。GitHub Pages で公開する
- [x] ストア掲載文（「単一用途」の説明を含む）：store/listing.md

**ストア審査上の留意点**

連絡先・会社台帳は独立した連絡先管理機能ではなく、「宛先台帳の自動作成」として誤送信防止の一部に位置づけて説明する。
